# Gladys Zendure — external integration

External integration that connects [Zendure](https://zendure.com) solar
batteries (SolarFlow) to [Gladys Assistant](https://gladysassistant.com),
built with the official JavaScript SDK
[`@gladysassistant/integration-sdk`](https://github.com/GladysAssistant/integration-sdk-js).

> **User documentation** (how to get your cloud key, local MQTT, transport
> badges, troubleshooting): [`docs/en.md`](docs/en.md) ·
> [`docs/fr.md`](docs/fr.md) · [`docs/de.md`](docs/de.md) ·
> [`docs/es.md`](docs/es.md). The store re-hosts these and Gladys links to them
> from the integration's Configuration screen. This README is the developer
> overview.

## What it does

- Discovers your Zendure devices through the Zendure cloud API, using the
  authorization key generated from the Zendure mobile app.
- Publishes read-only telemetry for 7 SolarFlow / Hyper models, in the Gladys
  energy categories: battery level, charge and discharge power
  (`battery-storage`), home output power (`home-output-sensor`), solar input
  power (`energy-production-sensor`).
- Optional **local MQTT** (native `Zendure/sensor/#` + legacy JSON), keyed by
  serial, with per-device **cloud fallback** and automatic recovery, surfaced
  as live transport badges (local / cloud / cloud-degraded / unreachable).

Device control (writable features) is planned — see the roadmap issue.

## Installation & updates

Requires **Gladys Assistant 4.86.0 or later** (`gladys_version` in the
manifest).

The integration is listed in the Gladys integration catalog (category
_Energy_): open **Integrations**, search for "Zendure" and install it. Every
release publishes the multi-arch image `ghcr.io/terdious/gladys-zendure:<version>`
(and `:latest`) and its GitHub Release, whose notes are the matching section of
[`CHANGELOG.md`](CHANGELOG.md).

To test a development build, paste the manifest
(`gladys-assistant-integration.json`) under **Integrations → Install an
integration → Developer mode**: the summary of a manual run of the **Build and
publish image** workflow prints the manifest already pointing at that build.

> **Developer mode updates.** The **"Force update"** button in the Supervision
> box only pulls a new **Docker image (the runtime)**. The **version shown**
> and the **configuration fields** (`config_schema`) are rendered from the
> **manifest pasted at install time** and do **not** refresh with the image:
> re-paste the manifest to pick them up.

## Configuration

The configuration form is generated by Gladys from the manifest
(`gladys-assistant-integration.json`):

| Key                 | Description                                                    |
| ------------------- | -------------------------------------------------------------- |
| `cloud_key`         | Zendure cloud authorization key (base64 token)                 |
| `poll_frequency`    | Telemetry refresh interval in seconds (10–3600)                |
| `enable_local_mqtt` | Read telemetry from the local MQTT broker, with cloud fallback |
| `feature_names`     | Language of the feature names of new devices (en, fr, de, es)  |

## Run it locally

```bash
npm install
GLADYS_HOST_API_URL="http://localhost:1443" \
GLADYS_INTEGRATION_TOKEN="<token>" \
GLADYS_INTEGRATION_SELECTOR="zendure" \
LOG_LEVEL=debug \
npm start
```

The three `GLADYS_*` variables are injected by the Gladys supervisor when the
integration runs inside its sandboxed container. The SDK reads them
automatically.

## Development

Node.js 22 or later.

```bash
npm install
npm run format:check   # Prettier
npm run lint           # ESLint
npm test               # unit + e2e + manifest + release helpers (node --test)
npx github:GladysAssistant/integration-store .   # store admission rules
```

Describe each change under `## [Unreleased]` in [`CHANGELOG.md`](CHANGELOG.md).
A release is cut from **Actions → Release → Run workflow** (patch / minor /
major): it bumps `package.json` and the manifest (`version` + `docker_image`,
Prettier layout kept), rolls the changelog, tags `vX.Y.Z`, publishes the
image and the GitHub Release. Dependabot keeps the SDK and the GitHub Actions
up to date.

## Troubleshooting

- **One device shows no values (or is slower than the others) while the rest
  work**: check the per-device transport badge in Gladys. If the device fell
  back to `cloud` (or is `unreachable`) while local MQTT is enabled, its
  firmware may have silently stopped publishing to the local broker — in the
  Zendure app, toggle the device's MQTT control OFF, save, then ON again; the
  device resumes publishing within a minute. The integration falls back to the
  cloud automatically in the meantime and returns to local on its own once the
  local messages resume (see the `telemetry:` transition lines in the logs).

## Translations

Every text the user reads ships in the four languages of the Gladys interface
(en, fr, de, es): the manifest (labels, descriptions, links, catalog
description), the runtime messages (connection status in
`src/devices/index.js`, degraded badge tooltip in `src/devices/solarflow.js`)
and the user documentation (`docs/<lang>.md`, same outline in every language).
`test/manifest.test.js` fails when one of them misses a language. The feature
names follow the `feature_names` option.
